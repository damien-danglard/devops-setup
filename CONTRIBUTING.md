# Contributing to DevOps Setup Guide

Thank you for your interest in contributing to the DevOps Setup Guide! This document provides guidelines and information about contributing to this project.

## 🌟 How Can I Contribute?

### Reporting Issues

If you find an error, outdated information, or have a suggestion:

1. Check if the issue already exists in the [Issues](https://github.com/damien-danglard/devops-setup/issues) section
2. If not, create a new issue with:
   - A clear and descriptive title
   - A detailed description of the problem or suggestion
   - Examples or references when applicable
   - The specific file(s) affected

### Suggesting Enhancements

We welcome suggestions for:
- New tools or technologies to cover
- Additional best practices
- New sections or topics
- Improvements to existing content
- Real-world examples and case studies
- Translations

### Contributing Code/Documentation

1. **Fork the Repository**
   ```bash
   git clone https://github.com/YOUR-USERNAME/devops-setup.git
   cd devops-setup
   ```

2. **Create a Branch**
   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/your-fix-name
   ```

3. **Make Your Changes**
   - Follow the existing documentation style
   - Keep the tone professional but accessible
   - Use clear examples
   - Ensure your changes are accurate and up-to-date

4. **Test Your Changes**
   - Review all modified files
   - Check for typos and grammatical errors
   - Verify all links work correctly
   - Ensure formatting is consistent

5. **Commit Your Changes**
   ```bash
   git add .
   git commit -m "Brief description of your changes"
   ```
   
   Follow these commit message guidelines:
   - Use the imperative mood ("Add feature" not "Added feature")
   - Keep the first line under 50 characters (72 maximum)
   - Add detailed description if needed after a blank line

6. **Push to Your Fork**
   ```bash
   git push origin feature/your-feature-name
   ```

7. **Submit a Pull Request**
   - Go to the original repository
   - Click "New Pull Request"
   - Select your fork and branch
   - Fill in the PR template with:
     - Description of changes
     - Related issue number (if applicable)
     - Type of change (documentation, bug fix, new feature)

## 📝 Style Guide

### Documentation Style

- **Language**: Content is in French. Maintain consistency with the existing language and tone.
- **Formatting**: Use Markdown formatting consistently
  - Use `#` for main titles, `##` for sections, `###` for subsections
  - Use code blocks with language specification: ```bash, ```yaml, ```javascript
  - Use bullet points for lists
  - Use tables for comparisons
- **Structure**: Follow the existing structure in each guide
  - Introduction
  - Core concepts
  - Practical examples
  - Best practices
  - References

### Technical Content

- **Accuracy**: Ensure all technical information is correct and current
- **Examples**: Provide practical, working examples when possible
- **References**: Include links to official documentation
- **Balance**: Provide both beginner-friendly explanations and advanced concepts
- **Neutrality**: When comparing tools, remain objective and explain trade-offs

### Code Examples

```bash
# Use comments to explain complex commands
command --flag value

# Show both command and expected output when helpful
$ echo "Hello World"
Hello World
```

## 🎯 Areas for Contribution

### High Priority

- **Tool Updates**: New tools or major version changes
- **Real-world Examples**: Case studies from actual implementations
- **Missing Topics**: Areas not yet covered in the guides
- **Error Corrections**: Fixing technical inaccuracies

### Medium Priority

- **Clarifications**: Making complex topics easier to understand
- **Additional Examples**: More practical examples for existing content
- **Cross-references**: Better linking between related topics in different guides

### Nice to Have

- **Translations**: English or other language versions
- **Diagrams**: Visual representations of concepts
- **Templates**: Reusable configuration templates
- **Scripts**: Helper scripts for common tasks

## 🔍 Review Process

1. **Initial Review**: Maintainers will review your PR within a few days
2. **Feedback**: You may be asked to make changes
3. **Discussion**: Complex changes may require discussion
4. **Approval**: Once approved, your PR will be merged
5. **Credit**: Contributors are acknowledged in the project

## 🤝 Code of Conduct

This project follows a Code of Conduct to ensure a welcoming environment for all contributors. Please read the full [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you agree to:

- Be respectful and inclusive
- Accept constructive criticism
- Focus on what's best for the community
- Show empathy towards others

## 📞 Getting Help

If you need help:

- **Questions**: Open a GitHub issue with the "question" label
- **Discussions**: Use GitHub Discussions for general topics
- **Problems**: Open an issue with detailed information
